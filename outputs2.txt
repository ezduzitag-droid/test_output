"""Q01 verification: filtered vs smoothed HMM regime probabilities (synthetic data only)."""
import numpy as np
from hmmlearn.hmm import GaussianHMM
from scipy.stats import multivariate_normal

rng = np.random.default_rng(7)

# --- synthetic 2-regime, 2-feature series (NOT market data) ---
T, K = 3000, 2
A_true = np.array([[0.98, 0.02], [0.05, 0.95]])
mu = np.array([[0.0005, 0.004], [-0.0010, 0.015]])      # [return, vol-proxy]
sd = np.array([[0.004, 0.0015], [0.012, 0.005]])
s = np.zeros(T, int)
for t in range(1, T):
    s[t] = rng.choice(K, p=A_true[s[t - 1]])
X = rng.normal(mu[s], sd[s])

TRAIN = 2000
model = GaussianHMM(n_components=K, covariance_type="full", n_iter=200, random_state=0)
model.fit(X[:TRAIN])                                     # parameters see only data < TRAIN

def forward_filter(model, X):
    """Causal filtered P(s_t | x_1..x_t) using fixed fitted params. O(T*K^2)."""
    K = model.n_components
    B = np.column_stack([
        multivariate_normal(model.means_[k], model.covars_[k], allow_singular=True).pdf(X)
        for k in range(K)])
    out = np.zeros((len(X), K))
    alpha = model.startprob_ * B[0]
    out[0] = alpha / alpha.sum()
    for t in range(1, len(X)):
        alpha = (out[t - 1] @ model.transmat_) * B[t]
        out[t] = alpha / alpha.sum()
    return out

filt = forward_filter(model, X)
smooth_full = model.predict_proba(X)                     # forward-backward over ALL data

# 1) last row of predict_proba on a window ending at t == filtered prob at t
ts = np.arange(TRAIN, T, 97)
err = max(np.abs(model.predict_proba(X[:t + 1])[-1] - filt[t]).max() for t in ts)
print(f"[1] max |predict_proba(X[:t+1])[-1] - manual filter| over {len(ts)} t: {err:.2e}")

# 2) look-ahead: smoothed (full-sample) vs filtered at the same t
test = slice(TRAIN, T)
dis = (filt[test].argmax(1) != smooth_full[test].argmax(1)).mean()
mad = np.abs(filt[test] - smooth_full[test]).mean()
print(f"[2] test region: argmax disagreement filtered vs smoothed = {dis:.3%}; mean |dP| = {mad:.4f}")

# 3) Viterbi label instability: do past labels change when new data arrives?
w1 = model.predict(X[:2500])
w2 = model.predict(X[:3000])
chg = (w1 != w2[:2500])
print(f"[3] Viterbi: {chg.mean():.3%} of labels for t<2500 changed after appending 500 obs "
      f"(max index changed: {np.where(chg)[0].max() if chg.any() else None})")

# 4) leakage consequence: accuracy vs true regime, filtered vs smoothed, test region
acc_f = (filt[test].argmax(1) == s[test]).mean()
acc_s = (smooth_full[test].argmax(1) == s[test]).mean()
print(f"[4] agreement with true regime: filtered={acc_f:.3f}  smoothed(look-ahead)={acc_s:.3f}")

# Q01-A - Regime classification without future information

## Original research question
How should our ML bot identify and classify market regimes using historical information such as volatility, momentum, volume, price movement, and correlations, without accidentally using information from the future?

## Research objective
Establish (1) whether an HMM is a sound regime-classification component, (2) exactly where look-ahead enters an HMM pipeline, (3) how to update classifications bar by bar, (4) how to expose uncertainty to downstream logic.

## Existing project context
- Obsidian vault and code repository: NOT ACCESSIBLE in this session. Steps 2 and 6 of the workflow are therefore NOT DONE.
- Known only from prior notes: AI_Trading_Lab works on public 5-minute spot data (ADA, BTC, DOGE, ETH, SOL, XRP vs USDT, Binance.US), public data only, no live trading. Whether it contains any regime code is unknown.

## Technical concepts (plain language)
- **Regime**: a persistent market "mode" (e.g., calm/trending vs. volatile) that changes return/volatility behavior.
- **HMM**: assumes a hidden regime s_t that follows a Markov chain (transition matrix A) and emits observed features x_t from a regime-specific distribution (Gaussian: mean mu_k, covariance S_k). Parameters: lambda = {A, mu, sigma, pi}. Two assumptions: observations depend only on the current state; transitions depend only on the current state (Wang et al. 2020, Sec. 2.2).
- **Filtering** P(s_t | x_1..x_t): uses only the past and present. Causal. The only legitimate quantity for live or backtested decisions.
- **Smoothing** P(s_t | x_1..x_T): also uses observations after t. Fine for descriptive research, leaks future information if used for decisions.
- **Viterbi**: most likely whole state path given all observations (also non-causal).

## Research findings
1. **The standard library call is non-causal at interior points.** hmmlearn documents `viterbi` as the most likely state sequence "given all emissions" and `map` (smoothing / forward-backward) as the individually most likely states "given all emissions". `predict_proba` returns posterior state probabilities (smoothed). Any value at time t from a window extending past t uses future bars.
2. **The causal quantity is available from the same API, with one trick.** The last row of `predict_proba(X[:t+1])` equals the filtered probability at t (the backward message at the final step is 1). Verified numerically (below). hmmlearn does not expose a public forward-only filter, so use the manual recursion below (O(K^2) per bar) rather than recomputing the window each bar.
3. **Parameters are a second leak channel.** Fitting the HMM on the full history and then reading regimes inside that history leaks through mu, S, A. Parameters must be fit only on data available at the refit time.
4. **State identity is unstable across refits (label switching).** The reference paper retrains daily on a sliding window and fixes meaning with a rule (lowest-return regime = bear, highest = bull).
5. **The reference paper is a design lead, not proof.** Wang, Lin, Mikhelson (JRFM 13(12):311, 2020): Gaussian HMM (hmmlearn), 3 states, features = daily return and a volatility proxy, trained on S&P 500 ETF data (Jan 2007 - Sep 2017), tested Sep 2017 - Apr 2020. Limitations I found in the text:
   - Per-regime strategy performance was computed from regimes decoded over the training period (hindsight labels).
   - Live regime detection used a *different* mechanism (KS-fitted distributions, PDF thresholds 0.3 and 0.5, not justified in the text) rather than HMM filtered probabilities.
   - K=3 was chosen using in-sample log-likelihood (Fig. 3), which generally improves as K grows, so it cannot select K on its own.
   - One out-of-sample window (~2.6 years), equities, daily bars; includes leveraged strategies; the text I read does not discuss transaction costs.
   - Its "volatility" is a mean-squared deviation of closing prices around a 10-day moving average, which is price-scale dependent.
   Transfer to 5-minute crypto is untested.

## How the technique works
Filtered recursion (fixed parameters), with b_j(x) the emission density of state j:

    alpha_t(j) = b_j(x_t) * sum_i alpha_{t-1}(i) * A[i, j]
    P(s_t = j | x_1..x_t) = alpha_t(j) / sum_k alpha_t(k)

Reference implementation and tests: `Q01_hmm_filter_verification.py` (same folder).

# Q01-B - Learning which strategy works in which regime, and proving it holds on unseen data

## Original research question
How should the bot learn which strategies perform best within each identified market regime, and how can it establish that those relationships remain effective on previously unseen historical data?

## Research objective
Define a procedure that builds a strategy-by-regime performance map and tests whether it generalizes, while controlling selection bias from testing many strategy-regime cells.

## Existing project context
Repo and vault not accessible this session (Steps 2, 6 not done). Depends on Q01-A (causal regimes), Q02 (switching), Q03 (selection policy), Q05/Q06 (overfitting, chronological validation), Q18 (costs).

## Technical concepts
- **Regime-conditional performance**: a strategy's return statistics computed only over bars where a given regime was active.
- **Selection bias**: with S strategies and R regimes there are S x R cells; picking the best cell by in-sample score is optimistic by construction.
- **PBO / CSCV**: Bailey, Borwein, Lopez de Prado, Zhu propose estimating the probability that the in-sample-best choice underperforms out of sample, using combinatorially symmetric cross-validation; they argue that standard hold-out is unreliable for investment backtests.

## Research findings
1. **The reference design** (Wang et al. 2020): backtest six factor models over a training period, decode regimes with the HMM, compute each model's per-regime Sharpe, choose the best model per regime, then run the rotation on a later period. This is the right skeleton; its weaknesses for our purposes: the per-regime table used hindsight regime labels and a single train/test split, and live detection used a different mechanism than the one used to build the table (so the table and the live signal were not guaranteed to describe the same regimes).
2. **PBO/CSCV verified at abstract level**: framework and CSCV implementation exist and are model-free and nonparametric. I did not read the full paper this session; implementation details are to be verified in Q05.
3. **Counting units**: 5-minute bars within a regime episode are strongly autocorrelated, so sample size should be counted in regime *episodes* and evaluated with block bootstrap, not in bars. (Engineering reasoning; not source-verified.)

## How the technique works (proposed procedure)
    for each walk-forward fold (train window -> purged/embargoed gap -> test window):
        # TRAIN
        regimes_train = filtered regime labels on train window (Q01-A)
        perf[s, r]   = net-of-cost stats of strategy s over bars in regime r  (train only)
        eligible[s,r]= episodes(s,r) and bootstrap-CI criteria satisfied (thresholds from baseline)
        mapping[r]   = argmax_s shrunk(perf[s, r]) over eligible, else fallback strategy
        # TEST (parameters frozen at train end)
        regimes_test = causal filtered labels using train-fit HMM
        returns_test = returns of mapping[regime_t] applied bar by bar, net of costs and switching costs
    aggregate returns_test across folds; compare against baselines

Baselines the regime-conditional rule must beat out of sample: (a) the single best strategy chosen in train, (b) equal-weight over strategies, (c) random mapping, (d) block-permuted regime labels (destroys regime information while preserving label statistics).
Stability check: rank correlation of per-regime strategy rankings between consecutive folds.
Overfitting control: treat each candidate mapping rule / hyperparameter setting as a trial and compute PBO via CSCV over the trial-by-time performance matrix (Q05).

## Application to this project
Gives the strategy-intelligence layer (architecture block G) a testable claim: "regime information adds net, out-of-sample value over the best single strategy". If it cannot show that, the map is not used.

## Acceptance criteria
- The regime-conditional rule beats baselines (a) and (c)/(d) out of sample, net of costs, with a block-bootstrap confidence interval on the improvement that excludes zero.
- Rank stability across folds and PBO are reported; promotion thresholds are set from the baseline distribution (random-mapping / permuted-label runs), not chosen arbitrarily.
- No component of the test window influences train-window mapping (future-perturbation test).

## Risk assessment
Few regime episodes per cell; regimes drift; multiple comparisons; costs and switching can erase small edges; a single-strategy baseline may simply win (which is a valid result).

Causal fix: the last row of predict_proba on a window ending at t equals the filtered (past-only) probability at t. I checked this numerically on synthetic data (difference 1.7e-12), and the script includes a manual bar-by-bar filter.
Size of the leak: on that easy synthetic data, using future information raised agreement with the true regime from 0.983 to 0.995. It disagreed with the causal version on 1.8% of bars, so the effect on real 5-minute crypto may be larger. My attempt to show that appending data changes past Viterbi labels found no change on the easy data, so I haven't shown that effect.
Second leak: fitting the model on the whole history also leaks, through its parameters. Refit only on past data, keep the states consistently labeled across refits, and normalize features using only trailing statistics.
